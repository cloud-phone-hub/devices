## 3. aidl: 'pid' can't be an out parameter because int can only be an in parameter

第一版把 `getPid` / `isServiceB` / `getServiceBCount` 的 int/boolean 写成 `out`：


## 4. 误判：把 getServiceBCount 当成「两个 out」

最初按「mangled 有 `(vector*, int*)`」推断声明是
`void getServiceBCount(out ServiceRecord[] services, out int count)`，两处都错：

1. int 不能 `out`（见上）；
2. 顺序也会反——aidl 生成规则是**返回值先写、出参后写**，两个 out 才是按声明序写。

反汇编才定案（Bp 侧读回包）：

```
e194: ldr x0, [sp, #0x8]      ; reply
e198: mov x1, x21             ; x21 = 第 2 个参数 = int*
e19c: bl  AParcel_readInt32   ; ← 先读 int
e1b8: mov x1, x20             ; x20 = 第 1 个参数 = vector<ServiceRecord>*
e1bc: bl  AParcel_readParcelableArray  ; ← 后读数组
```

⇒ 回包序是 `[count][services]`，对应**返回值 + out**：
`int getServiceBCount(out ServiceRecord[] services);`
同理 `int getPid(in String)`、`boolean isServiceB(in String)`。
用探针工程确认了生成序：

```
$ aidl --lang=ndk --structured --stability=vintf … IT.aidl     # int f(out int[] a)
  33: _aidl_impl->f(&out_a, &_aidl_return);
  39: AParcel_writeData(_aidl_out, _aidl_return);   ← 返回值先写
  …:  AParcel_writeData(_aidl_out, out_a);          ← 出参后写
```

**修正**：改 3 个方法签名 + 实现里的 `*_aidl_return`；其余「只有一个出参」的方法
（数组/结构体）保留 `out`——回包只有一项时两种写法 wire 完全相同。

## 5. `hal build` 默认产物根 android15，07 的变体根是 android16

```
$ out/bin/cdh-vendor hal build vendor.qti.hardware.servicetrackeraidl
    写 bin/hw/…-service   -> out/vendor/android15/bin/hw/… sha  f2f05a1d…

$ out/bin/cdh build-vendor … --dry-run | grep servicetracker
  HAL 模块:  …（变体 default，变体产物根 out/vendor/android16，产物齐全但源码/配置已变 -> 重编）

$ out/bin/cdh build-vendor …            # 实跑
    写 bin/hw/…-service   -> out/vendor/android16/bin/hw/… sha  91ff07dc…
```

同一份源码两个产物根、两个 sha（`f2f05a1d…` vs `91ff07dc…`），是 `-DCDH_ANDROID15`
之类的宏与 sysroot 差异导致，**不是错误**。回读镜像时必须拿 `android16` 的那份比。
