## ss9380 取样环境与手法（原设备侧 README 并入）

- 机型指纹：`samsung/pa3qzcx/pa3q:16/BP4A.251205.006/S9380ZCSDCZH1:user/release-keys`
- 盘集路线：官方三星 super 零改动 + `patch.img`（vendor / vendor_dlkm / odm 三子树，
  vdc 只读挂 `/mnt/patch`）+ 自编 lineage 6.12.81-4k-cdh 内核
- 最终盘集：`patch.img` sha256 `53e483856316d50c05f117efeb13d9b2012aca02bf9e0afe760700a156f6259d`
  （`engine/out/tmp/ss9380-build14.log`，含 sepolicy 片段第一～十段）；
  后续健康 HAL 与 etc 对齐两轮分别为 `1184adc64d50` 与 `5f81a5ecf385`
- 实例：daemon `http://127.0.0.1:9050`，adb `127.0.0.1:5911`、VNC `5912`、console `5910`；
  历史实例编号：失败态 `index 1`~`index 3`，第九/十段首次通过 `index 4`，
  健康 HAL 修复后 `index 3`/`index 5`，etc 对齐后 `index 4`
- 本机型运行时**没有** `precompiled_sepolicy`（init 现场用 `/system/bin/secilc` 编译），
  所以改 sepolicy 片段必须从 `07_build_vendor` 起重跑（片段在该阶段注入 patch 装配树）
- 「官方 system + lineage vendor」意味着 plat 是官方的、vendor 是 lineage 的，
  OneUI 把一批原本写在 plat 的权限挪到了 vendor 侧（三星自己的 `vendor_sepolicy.cil` 里）。
  这类缺失都以 `avc: denied` 暴露，取证顺序固定：① `dmesg | grep -o 'avc:.*' | sort | uniq -c | sort -rn`
  看全貌；② 到官方 `vendor_a.img` 的 `/etc/selinux/{vendor_file_contexts,vendor_sepolicy.cil}`
  找对应原句；③ 类型名带版本后缀，写片段时用 `{{vers}}` 占位（本机型
  `plat_sepolicy_vers.txt` = `202504`）
- 三条踩过的坑：① **属性域按最长前缀匹配**，`sys.*` 归 `system_prop`，兜底行
  `* default_prop` 只对没命中任何前缀的属性生效（第一版第九段错写成 `default_prop`，secilc
  编得过、进镜像，运行时照样被拒）；② **`adb shell` 里的反斜杠会被吃掉**，`grep '^sys\.'`
  返回空导致误判，改写成 `grep -nE '^(sys\.|\*)'`；③ **计数要排除 adbd 回显**，`adb shell`
  的命令行本身会被 `adbd` 写进 `qemu.log`，`grep -c` 会把这一行算进去（实测造成过 0/1 假信号）
- 构建编号提醒：`solution.md` 里手写的 build 序号与 `engine/out/tmp/ss9380-build*.log`
  的编号并不一一对应（现存缺 11、15），引用产物**以 `patch.img` 的 sha256 为准**
