## 备注

- **图形栈验证的两个「别踩」**（#140 实测）：① 运行态 `setprop ctl.restart surfaceflinger`
  会让 HyperOS 窗口状态回不来（launcher 进程消失、`mCurrentFocus=null`、满屏
  `FAILED_TRANSACTION`，`am start`/`stop;start` 都救不回）——改图形属性只能「改完冷启动实例」；
  ② `pm enable <data-app 包>` 会让 system_server 崩一次并最终窜进 recovery
  （`recovery: Boot command: boot-recovery`）。两者的恢复手段都只剩
  `POST /api/stop` + `/api/start`（**必须 JSON body**）或 QMP `{"execute":"system_reset"}`。
- **图形自省通路在本机全断**：`dumpsys SurfaceFlinger` 只回 `FAILED_TRANSACTION`、
  `cmd gpu vkjson` 回 `Failure calling service gpu`、`screencap` 挂住、`uiautomator dump` 回
  `null root node`、`input keyevent` 被 `INJECT_EVENTS` 拒。判 GL/渲染器只能绕道：
  `/proc/<pid>/{maps,task/*/comm,fd}`（看是否 llvmpipe 线程 / libLLVM 映射 / renderD128 fd）。
- **HyperOS `data-app` 只能从桌面点开**：`am start -n <pkg>/<Activity>`、`am resolve-activity`、
  `monkey -p … -c LAUNCHER` 对天气 / 计算器这类 `data-app` 一律报「组件不存在」，
  别据此判断「包坏了」——`dumpsys package` 里组件与 filter 都在。
- **取样环境**：`out/core/daemon/runtime/popsicle_cn_OS3.0.319.0.WPBCNXM/<实例号>/qemu.log`；
  daemon 在 9050，popsicle 在 images 表 index 5，实例端口 console 5910 / adb 5911 / vnc 5912。
- **adb 口径**：必须在**项目根**执行 `out/qemu/dist/darwin/bin/adb`（engine 下没有 `out/qemu`），
  TCP 设备先 `adb connect 127.0.0.1:5911`，其余查询一律带 `-s 127.0.0.1:5911`。
- **构建口径**：`cd engine && ./out/bin/cdh device build popsicle --from build_vendor`（07→11），
  日志写项目根 `.tmp/`（engine 下没有 `.tmp`）。
- **engine HAL 产物落 patch 层**：`out/devices/xiaomi/popsicle/OS3.0.319.0.WPBCNXM/patch/stage/root/vendor/`，
  运行时挂 `/mnt/vendorpatch`；`vendor/bin/hw/` 只有 6 项不代表没装 HAL。
- `screencap -p`（`exec-out` 或写 `/data/local/tmp`）在本机型会挂住，首屏证据改用
  `dumpsys activity activities` 的 `topResumedActivity`；与 oriole 同类现象。
