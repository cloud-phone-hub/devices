## 2. 回收失灵的现场

发现时 `ps` 里同时列出两个 `wifi-host-service`：

- 92706：当日为验证 WiFi 修复，在仓库根以**相对路径**手工启动
  （`./out/qemu/dist/darwin/libexec/wifi-host-service ...`）；
- 另一份由 daemon 拉起（绝对路径）。

92706 不在实例目录的 `backend-pids` 清单里（清单只记 daemon 自己的子进程），
进程表扫描也没命中它，于是 daemon 重启 / 实例停止都回收不到它，它一直占着
`/tmp/stage-007d12b0/wifi-data.sock`。

处置：先 `kill -TERM 92706` 清掉旧网关，再修 `reap.go` 后重编译并重启 daemon。

## 3. 反证（修复前逻辑）

旧代码只用 `fields[0]` 与发布根做前缀比较：

```go
exe := fields[0]
if !strings.HasPrefix(exe, qemuRoot+string(filepath.Separator)) {
    return false
}
```

相对路径 `out/qemu/dist/darwin/libexec/wifi-host-service` 不以
`/Volumes/work/cloud-phone-hub/out/qemu/dist/darwin/` 开头 → 直接 false →
`listBackendProcesses` 漏掉 → 不回收。
