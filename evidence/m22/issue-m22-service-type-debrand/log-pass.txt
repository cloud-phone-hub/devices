## F. avc 统计（记录级口径，沿用 #58）

日志快照：`out/core/daemon/runtime/m22_12.5.0.0A/39/qemu.log`
12,514,453 B / 90,373 行 / sha256 `371edc6f…` / kernel ts 0.0–478.4 s。

统计脚本（按**完整记录**而不是按行：从 kernel `[...][  Tn] SELinux:` 与 logd
`… I auditd  :` 两个上报前缀起找 `avc: denied { … } scontext=… tcontext=…`）：

```python
import re, collections
raw = open(log, 'rb').read().decode('utf-8', 'replace')
KER = re.compile(r"\[\s*\d+\.\d+\]\[\s*T\d+\]\s*SELinux:\s*")
AUD = re.compile(r"\d{2}-\d{2} \d{2}:\d{2}:\d{2}\.\d{3}\s+\d+\s+\d+\s+[IWEF] auditd\s*:\s*")
NF  = re.compile(r"avc:\s+denied\s+\{([^}]*)\}\s+for\s+(.*?)\s+scontext=(\S+)\s+"
                 r"tcontext=(\S+)\s+tclass=(\S+)(?:\s+permissive=(\d))?")
names = (...8 个 hal_*_service...)
recs = [NF.search(raw[m.end():m.end()+700]) for m in list(KER.finditer(raw)) + list(AUD.finditer(raw))]
```

输出：

```
结构完整 avc 记录 5379 (ker 379 / aud 5000)
8 类型命中: hal_servicetracker_service 3, hal_meizu_charging_service 3, hal_aw_light_service 3,
           hal_awa_reality_service 3, hal_idiag_service 3, hal_realitytap_service 3,
           hal_sensor_aux_service 3        （合计 21）
pid: 8292 8293 8294 8295 8296 8297 8298
scontext: u:r:pioneer:s0 (21)     permissive: 1 (21)
perf2 关键字记录: 0
cdh_*_service 记录: 0
Compiling SELinux policy 1 | InitFatalReboot 0 | Failed to resolve 0
```

判读：

1. **perf2 相关 avc 记录 0**（对照实例 37 的 1653 条 `cdh_perf2_service`），改名没有
   把 #58 修好的授权改坏。
2. 21 条命中全是 `scontext=u:r:pioneer:s0` + `permissive=1` + pid 连续（8292–8298）：
   就是我本轮验证时自己跑的 `service check <name>`（uid 2000 shell 即 pioneer 域），
   一个名字一条，再被 kernel 与 logd 双通道各记一次。pioneer 是 permissive 域，
   只记不拦；**system_server 侧 0 条**，说明 `add/find` 授权面没被打破。
3. `Compiling SELinux policy` 1 次、`InitFatalReboot` 0、`Failed to resolve` 0：
   策略在 boot 期一次编译通过，没有 duplicate type。
