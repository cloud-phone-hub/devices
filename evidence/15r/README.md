# 15r：OnePlus 15R（ColorOS 16.0.10.500_EX01 / 骁龙 SM8750 `canoe` / Android 16）

9 条机型条目：#127 是「官方 odm 顶层 build.prop 未纳入 patch 覆盖」导致的 OplusWifi
SmartAntenna 空 converter，system_server 在 `sys.boot_completed=1` 之后每 ~80 秒自杀一轮；
#128 是官方 power.stats 实现与本机自建空 HAL 抢注同一个 AIDL 实例，每 ~5 秒 SIGABRT
并让我们的服务名字被 servicemanager 摘掉；#129 是 `/vendor/etc/media_config.xml` 缺失
让两个自编 c2 store 每 ~5 秒 status 1 退出、`IComponentStore/default1` 与 `default9`
始终没有实例；#130 是 `/odm` 由「逐条遮蔽 23 个路径」改为整棵重定向，并记下「mount(2)
的目标路径同样过 getname_flags」这条必须配自映射护栏的坑；#131 是 `/odm` 整棵后
`com.android.nfc` 失去 HIDL 实现而每 0.1 秒崩一次，把 AMS 五条线程堵死 75 s 直到
`sysrq: Resetting`；#132 是我们自研的 wifi 数据面直桥在 kthread（进程上下文）直接调
`netif_receive_skb()`，故意违反「调用者须已禁用 BH」的 API 约定，让 `tcp_delack_timer`
能在同一 CPU 上重入并抢自己持有的 `sk_lock`，136 s 后整机所有 CPU 都在 TCP 锁上自旋；
#133 是 #131 的反向复核——按用户要求集成自研 AOSP NFC HAL 并解除 NfcNci 屏蔽后，HAL 侧
全部达标（服务 running、`INfc/default` found），但 `com.android.nfc` 仍以 ~7 次/秒崩，
崩点在 ColorOS 私有的 `IOplusNfc`（云机没有 hwservicemanager、`/odm` 只剩 build.prop），
AOSP `INfc` 根本不在那条链上，于是屏蔽恢复生效。
#151 是本轮新引擎流水线首轮起机暴露的两段同源问题：官方 vendor 件把 GPU 后端名写成物理 SoC 的（`egl=adreno`、`vulkan=adreno`），云机树里只有 mesa/virtio 实现件，libEGL 与 ColorOS 的 libhwui 都是「按属性拼库名、拼不到就 assert」，于是先 SF 崩溃循环、补完 egl 又变成三个 UI 进程崩溃循环 + 全黑屏。
#158 是到桌面后 VNC/noVNC 完全无法操作界面：清单漏写 `modules.input` 段，daemon 回退默认三件套（未开 `abs-to-mt=on`），而 lineage-23.2 底盘的 `/vendor/etc/excluded-input-devices.xml` 把 `QEMU Virtio Tablet` 排除，只剩 `QEMU Virtio MultiTouch` 被打开，QEMU 往后者发的单指 `ABS_X/ABS_Y` + `BTN_LEFT` 因不在多点触控轴位图内被 guest 内核静默丢弃。
前五条都不是配置错误，是「ColorOS/厂商组件假设了官方 HAL、官方内核能力、官方 vendor
布局」与「云机没有」的冲突；#132 不同，是我们自己代码违反上游约定。

## 备注

- **取样环境**：`out/core/daemon/runtime/15r_16.0.10.500_EX01/<实例号>/qemu.log`；
  daemon 在 9050，15r 在镜像表 index 2，实例端口 console 5910 / adb 5911 / vnc 5912。
- **adb 口径**：`adb connect 127.0.0.1:5911` 后所有查询带 `-s 127.0.0.1:5911`。
  注意宿主机上可能同时挂着别的实例（`adb devices` 里的硬件序列号那台**不是**本机），
  不指定 `-s` 会读到别的机型（例如 `ro.boot.hardware=mt6833`）。
- **构建口径**：`cd engine/build && ../out/bin/cdh device build 15r --only <阶段>`；
  `--only` 只接单个阶段，多阶段就分多次跑（顺序 `build_odm` → `build_vendor_boot` →
  `build_patch` → `pack_vda`）。改 `cdh_redirect.rules` 必须重跑 05 与 11（规则进
  vendor_ramdisk），改 `odm/` 覆盖树必须重跑 06 → 09 → 11。
- **官方分区是 EROFS**：查 `odm_a.img` / `system_a.img` 用
  `dump.erofs --path=/ --ls`、`dump.erofs --cat --path=/build.prop odm_a.img`
  （`--path` 是镜像内绝对路径；`debugfs` 只适用于 vendor/vendor_dlkm）。
- **反编译**：ColorOS 的 WiFi 定制在 `/system_ext/framework/oplus-wifi-service.jar`，
  `fsck.erofs --extract` 解出后 `jadx -d <out> --no-res --no-imports <jar>`。
