要看的四行：

1. `kernelsu: 应用 0001-shell-profile.patch` / `0002-…`：补丁在模块 Kbuild 解析阶段应用，
   `source/kernel/policy/shell_profile.c` 等由补丁生成后才参与编译；
2. `-- KernelSU version: 32680`：`KSU_GIT_VERSION=2680`（v3.3.1 提交数）+ 30000，说明
   `export` 的变量穿过递归子 make 生效；
3. `LD [M] …/source/kernel/kernelsu.ko`：`obj-$(CONFIG_KSU) += source/kernel/` 递归编译，
   产物在子目录，03 按整棵模块树查找唯一命中；
4. `vermagic: 6.6.127-4k-g4d42ee3d41c6`：与 `lineage-22-6.6` 内核对得上。

`Module.symvers is missing` 与 217 条 undefined 告警是「实验环境只 `modules_prepare`、
没编 vmlinux」造成的；真实构建用 02 的 `Module.symvers`，`KBUILD_MODPOST_WARN=1` 只需
覆盖 KernelSU 那几个运行时自解析的符号。

补丁链等价性另有两次校验：

    # ① git archive v3.3.1 → 应用 0001、0002 → 与 cdh 分支工作树逐文件比对
    $ git apply --check 0001-shell-profile.patch && git apply 0001-shell-profile.patch
    $ git apply --check 0002-kernel-6.9-tracepoint-prio.patch && git apply 0002-kernel-6.9-tracepoint-prio.patch
    $ diff -r patchcheck/source ref/source && echo '✓ 补丁链与 cdh 分支一致'
    ✓ 补丁链与 cdh 分支一致

    # ② 同一份无 .git 的工作树上重复解析（模拟 modpost 阶段）不再重复应用
