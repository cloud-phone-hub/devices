# 通过态：**无** —— 本条未闭环

天气（`com.miui.weather2`）在本轮全部实验里都是同一个失败链，没有出现任何「能起来」的配置。
按 AGENTS 的约定，本文件用来记录：**已证伪的方向**、**已排除项**，以及本轮实验现场
（改属性 → 重启实例 → 误入 recovery）的处置与复原结果，避免下一个人重复踩。

---

## 1. 已被证伪的方向

| 方向 | 做法 | 结果 |
| :--- | :--- | :--- |
| 用软件 Vulkan ICD 顶上 | 上一轮试过 lavapipe（`vulkan.lvp_mesa3d.so`）与 SwiftShader/pastel | 用户明确否决「不应该考虑软渲染」，本轮不再作为方案 |
| 关掉 GLES 的强制软件开关 | `setprop persist.sys.force_sw_gles 0` + 冷启动实例 | 天气仍未起来；但本节**不能**用「失败链逐字不变」来证明（受下一条限制，改完属性后已无法再用 `am start`/`monkey` 拉天气）。真正的依据是失败点在 Vulkan 设备枚举，而该属性只影响 `libEGL` 的 GLES 驱动选择 |
| 运行态重启 SurfaceFlinger 让新属性生效 | `setprop ctl.restart surfaceflinger` | **事故**：SF 起来了（pid 27205，有 `RenderEngine` blur 日志、打开 4 个 `/dev/dri/renderD128`），但 HyperOS 窗口状态被打坏——`pidof com.miui.home` 为空、`mCurrentFocus=null`、`mFocusedApp=null`、40 条 `FAILED_TRANSACTION`；`input keyevent 3` / `am start ...Launcher` / `stop; start` 均救不回。**不要再用这条验证图形** |
| 用 `pm enable` 修「组件解析不到」 | `pm enable com.miui.weather2` / `pm enable com.miui.weather2/.ActivityWeatherMain` | **事故**：组件那条直接抛异常栈，随后 system_server 崩、系统重启，最终窜进 recovery（`recovery: Boot command: boot-recovery`）。**不要对这个 build 跑 `pm enable`** |

## 2. 已排除项（都不是原因）

| 怀疑点 | 实测 | 判定 |
| :--- | :--- | :--- |
| 天气包被禁用/隐藏 | `dumpsys package com.miui.weather2`：`installed=true hidden=false suspended=false stopped=false notLaunched=false quarantined=false enabled=0`；`pm list packages -e` 命中 | 排除 |
| 缺 Flutter 引擎 so | APK 里 `libhyper_os_flutter.so` / `libapp.so` / `libweather_app.so` 齐全且为 Stored（可 mmap） | 排除 |
| 换渲染后端 | `am start --ez enable-impeller false --ez enable-software-rendering true` | HyperOS 场景框架忽略，仍 `Using the Impeller rendering backend (Vulkan)` |
| 内核没开 virgl | qemu.log：`[drm] features: +virgl +edid +resource_blob +host_visible` | 排除 |
| 设备节点缺失/权限/SELinux | `/dev/dri/card0`、`renderD128` 都是 `crw-rw-rw- system graphics u:object_r:gpu_device:s0`；`dmesg \| grep avc \| grep dri` = **0** | 排除 |
| Mesa 没编 virgl 驱动 | `/vendor/lib64/libgallium_dri.so`（48,771,688 B）内 `virgl=6 swrast=1 kms_swrast=0` | 排除 |
| PCI 身份不全导致 loader 不认 | `/sys/class/drm/renderD128/device/{vendor,device,class,subsystem_vendor,subsystem_device}` 齐全（0x1af4 / 0x1050 / 0x038000 / 0x1af4 / 0x1100），uevent `DRIVER=virtio-pci` | 排除 |
| guest 侧 Vulkan 自省能拿到设备信息 | `cmd gpu vkjson` → `Failure calling service gpu: Failed transaction`；`dumpsys SurfaceFlinger` → `FAILED_TRANSACTION` | 采不到，不是结论 |
| GLES 已落 llvmpipe | settings(9353)/surfaceflinger(603) 内 llvmpipe/swrast 线程 **0**、libLLVM 映射 **0**、settings 持有 4 个 renderD128 fd | **推翻**（详见 `solution.md` 五-4） |

## 3. 实验现场处置记录

1. **实例 21 两次重启**（均为「改属性 + 冷启动」，不是运行态重启 SF）：
   ```
   curl -s -X POST http://127.0.0.1:9050/api/stop  -H 'Content-Type: application/json' \
        -d '{"spec":"popsicle_cn_OS3.0.319.0.WPBCNXM","index":"21"}'
   curl -s -X POST http://127.0.0.1:9050/api/start -H 'Content-Type: application/json' \
        -d '{"spec":"popsicle_cn_OS3.0.319.0.WPBCNXM","index":"21"}'
   ```
   （`/api/stop?spec=&index=` 走 query string 会回 `{"error":"请求体须为 …"}`，必须 JSON body。）
   冷启动 ~40 s 到 `sys.boot_completed=1`，`pidof com.miui.home` 有值、焦点回到
   `com.miui.home/com.miui.home.launcher.Launcher`。
2. **误入 recovery 的恢复**：`pm enable` 之后 guest 反复重启并进 recovery
   （qemu.log：`recovery: Boot command: boot-recovery` / `recovery: Clearing BCB`）。
   因 adbd 变 `unauthorized`、guest shell 通道无响应，改用 QMP 硬复位：
   ```python
   # out/core/daemon/runtime/popsicle_cn_OS3.0.319.0.WPBCNXM/21/qmp.sock
   {"execute":"qmp_capabilities"}  -> {"return": {}}
   {"execute":"system_reset"}      -> {"event":"RESET"}
   ```
   复位后 40 s 回到 `sys.boot_completed=1`，桌面正常。
3. **收尾复原（本轮结束时实测）**：
   ```
   sw=1 trace=[]
   ls /data/local/tmp/  →  cph-storage-align.log  cph-wifi.log  dalvik-cache
   ```
   `persist.sys.force_sw_gles` 回到基座的 `1`、`debug.egl.trace` 已清空、
   本轮落的 `w.log` / `w-pub.log` / `hwtest` / `b` 全部删除。

## 4. 复现路径（下次直接照做）

- **天气只能从桌面图标点开**：这套 build 上 `am start -n com.miui.weather2/.ActivityWeatherMain`
  与 `am resolve-activity` 一律回 `Activity class … does not exist`（`com.miui.calculator` 等
  `data-app` 同样如此），`monkey -p … -c LAUNCHER` 回 `No activities found to run`。
  `input keyevent` 也被 `INJECT_EVENTS` 拦住（`SecurityException`），`uiautomator dump` 回
  `null root node`、`screencap` 挂住。→ 现场复现只能人工点图标，或改用 VNC（5913）截图。
- 采日志用 adb：`out/qemu/dist/darwin/bin/adb -s 127.0.0.1:5911 logcat -d -v brief`；
  需要 root 才能读的文件（如 `/data/local/tmp` 下 root 0600 的日志）走
  `engine/out/tmp/chsh.sh 'cp … /data/local/tmp/x && chmod 666 /data/local/tmp/x'` 再 pull。
