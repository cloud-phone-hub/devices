## 3. 运行时 init 按「后读覆盖先读」把厂商真值盖回去

$ grep -n "Overriding previous property" engine/out/tmp/cph2797-fail-qemu.log | head
645:[    0.542688][    T1] init: Overriding previous property 'ro.hwui.use_vulkan':'false' with new value 'true'
（全文 22 条同类留痕。逐条比对后，只有本条是「前值 = 基线收口值、后值 = 厂商原值」，
即收口被盖回；其余要么是厂商件自身两段同名行（dalvik.vm.*、debug.sf.*、
ro.board.platform 等），要么是「前值 = 厂商原值、后值 = 基线收口值」，
例如同一轮的 `ro.opengles.version:'196610' with new value '196608'`，方向相反、
收口生效。）

后果链：本轮（run1）的引导在更早的 FRP 卡点上就死了（system_server phase 500 崩，
见 engine/evidence/cph2797/issue-cph2797-frp-block-device-missing/），所以这份 logcat
里 `couldn't find an OpenGL ES implementation` / surfaceflinger / vulkan 计数均为 **0**，
use_vulkan 被盖回的渲染侧后果在本机型没有直接现场；该后果的崩溃形态见同链条的
#151（15r：`ro.hwui.use_vulkan=true` → SkiaVulkanPipeline → 无 vulkan.adreno.so →
`gpuCount` assert，battery/launcher/systemui 三进程自杀）。
本条的证据只到「产物有两行、运行时读到最后那行、清单的收口没生效」这一层——
这已经足以判定「按清单装配」这个口径被破坏。
