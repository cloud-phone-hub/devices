## 第 2 节：符号版本逐个对账（modversions CRC 全匹配）

口径：解析每个 `.ko` 的 `__versions` 段（`struct modversion_info {u64 crc; char name[56]}`，
每项 64 B），与同目录 `Module.symvers`（`0xCRC<TAB>symbol<TAB>module<TAB>export`）逐名比对。

```console
$ python3 <校验脚本>   # 解析 __versions + Module.symvers 逐名比对
cdh_device_info.ko               crc条目=39 匹配=39 不一致=0 不在Module.symvers=0
cdh_goodix_fingerprint.ko        crc条目=4  匹配=4  不一致=0 不在Module.symvers=0
cdh_input_identity.ko            crc条目=8  匹配=8  不一致=0 不在Module.symvers=0
cdh_media.ko                     crc条目=75 匹配=75 不一致=0 不在Module.symvers=0
cdh_redirect.ko                  crc条目=32 匹配=32 不一致=0 不在Module.symvers=0
```

`不一致=0` 是「03 编出来的模块能被 6.12.81 内核加载」的硬证据：任何一条 CRC 对不上，
内核 `load_module` 阶段就会 `disagrees about version of symbol` 直接拒载。

要点：

- `options cdh_media allow_userptr=1` 是 `virtio_media/module.json` 声明的那条，
  也是 v4l2_codec2 能用 USERPTR 的前提（没有它 V4L2 会清掉 USERPTR 能力位、
  DMABUF 又恒被拒 → codec2 拒绝启动）；

- `alias virtio:d00000030v* cdh_media` 是 virtio-video 的 device id（0x30），
  说明 `.modinfo` 里的 alias 被原样写进索引，**不靠 udev 热插拔也能按 id 自动加载**；
- 五份索引全部来自本次注入的 12 个模块的 `.modinfo`：`alias` 只有 7 行，基座镜像里原有的
  alias 一条不剩（`modules.load` / `dep` / `alias` / `options` / `softdep` 全量重建，
  AGENTS 第 6 条的「全量重建」）。
