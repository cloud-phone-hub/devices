## 2. 大流量下行永久卡死（链路丢帧）

宿主 wifi-host-service.log：

```
2026/10/28 01:36:59 [link] 发送队列满，丢帧（累计 12200）：对端未排空
```

20MB 下载停在此处，guest `/data/local/tmp/dl.bin` 约 15KB。网关 TCP 无重传，

## 6. guest→host 上行静默丢字节（seq 未校验）

旧二进制 `90fb3ac9…`，guest 上传 20MB（源 `out/tmp/speed/payload.bin`，
20971520 字节，sha256 `cd52d81e…`）到宿主 18081 接收器
（`out/tmp/wifi-evidence/pre-ingest-upload.log`）：

```
connected from ('192.168.31.230', 63245)
received 20968304            # 少 3216 字节
# 落盘 up.bin sha256
c9f9513e4d4cbf221f4b1bd65e9dd530bf12a4c3e26c0b9eeebdc8f9ea657960
```

同时段网关日志既无 `非法以太帧`、也无 `读帧失败/重同步/写出口失败`，
`[stat] drop=0 reset=0`。即：guest→host 链路丢了一帧，而网关既不看 TCP seq
也不校验，空洞之后的段照常写进上游流、ACK 还越过了空洞，guest 因此不会重传，
上游文件就在无任何告警的情况下少了一段。

## 7. captive 空响应（204 发完即 Closed，重传被忽略）

`out/tmp/wifi-evidence/final-stab-120-newbin.log`（二进制 `55ca32e6…`，120 轮长稳）
第 107 轮：

```
107 03:07:37 ip=1 gw=1 captive= baidu=HTTP/1.0 200 OK
```

同轮 baidu 正常、网关 `drop=0 reset=0`、无读写错误。代码审查：captive 连接在
`respondCaptive` 里发完 204+FIN 立即 `stage=Closed`；一旦 204/FIN 在 hvc10 丢帧，
guest 重传的请求段落在 Closed 状态，被 `handleTCP` 直接忽略，不会再有任何响应
（guest 校验 5s 后超时）。修复后用 captive 专项复测（结果见 `log-pass.txt` 第 5 节）。
