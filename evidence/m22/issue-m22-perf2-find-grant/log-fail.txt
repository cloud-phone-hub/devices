## A. 采集环境

- 设备/实例：MEIZU 22（`m22_12.5.0.0A`），实例 **37**（已停机，日志冻结）。

  不会被翻转冲掉）。

## D. 口径说明

- **两条上报通道**：SELinux 拒绝会由 kernel 直接打到串口（`SELinux: avc:`），也会被
  logd 以 `auditd` tag 再打一遍；本实例上两路覆盖不均（kernel 454 / auditd 1100）。
  所以本文件只报「能逐字段核对的上报**条数**」（合计 1554），不声称它是「唯一拒绝事件数」；
  关键是两个实例用**同一口径**，因此 1554 → 0 的对比成立（见 `log-pass.txt` E 段）。
- **为什么不能按行统计域**：串口是字节流 + 多路复用，QEMU 的 `cgl-headless 大帧`
  统计会把上一条 guest 输出插进 avc 行前面，于是一行里可能有两条不同的 avc。
  若用「行内第一个 `scontext`」归属域，就会把前面那条 avc 的域算到 perf2 头上。
  本轮实测就踩到了：按行首 `scontext` 统计会得到 24 个域，其中
  `pioneer` / `hal_face_default` / `hal_drm_clearkey_aidl` / `traceur_app` / `audioserver`
  这 5 个是假的——它们来自 `denied { find } for … name=window` 之类的别的 avc，被
  `perf2.IPerf` 字样拼进同一行而误命中。剔除后真实的 perf2 客户端是 19 个域。
- **片段**：66 行里 perf2 的字段被截断（`tclass=` 或 `tcontext=` 缺段），无法确认域，
  因此只计行数、不进域表；它们不改变结论（迁移后记录数为 0）。
- 迁移前 `logcat -b all` 曾统计到 90 行同类 avc（实例 37 缓冲内）；本文件用完整的
  串口流水重取，数字更大，两者窗口不同，不冲突。
- **更正**：本轮此前记过「`grep` 不带 `-a` 会把串口日志当 binary 而漏计（434 vs 1217）」，
  复测**未能复现**——本机对 `qemu.log` 用 `grep -c` 与 `grep -a -c` 计数一致
  （`grep -c perf2` = 3035 / 3035）。带 `-a` 仍是稳妥写法（日志含控制字节），但
  计数差异不成立，故本文件只保留实测数字。

可复现的一行命令（记录级统计的交叉校验）：

```sh
grep -a -c 'denied  { find }.*perf2\.IPerf' <qemu.log>   # 本文件：1620
grep -a -c 'Could not find.*perf2'            <qemu.log>   # 本文件：837
```
