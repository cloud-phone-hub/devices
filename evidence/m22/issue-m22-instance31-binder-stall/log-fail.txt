pid 861 = surfaceflinger，pid 972 = system_server。也就是说：
SurfaceFlinger 往 system_server 灌 oneway，system_server 的 **async 缓冲池（512 KiB）**被填满，
之后所有 async binder 事务一律 -28，客户端据此把 system_server 判成 dead。

== 为什么不是「内存不足」==
MemTotal 7,760,724 kB / MemAvailable 4,848,492 kB（cached 5.0 GB），并没有在回收压力下打转。
`top` 里那行 “Swap: 6291452K total, 6291452K used” 是假的（显示 hook 的产物）：

  $ adb shell cat /proc/swaps        -> 只有表头，没有任何 swap 设备
  $ adb shell free -m               -> Swap: 0 0 0

真瓶颈是 binder async 池（见上面的 spamming oneway / no space left），不是内存。
