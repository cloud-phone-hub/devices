## E. 实例 37：HAL 自己把「开不了」说清楚，进程不再被 Watchdog 打死

# 场景：m22 起机后 com.android.nfc（pid 1326）一直停在 OFF。
# 触发 enable 的三条路都有障碍（见 solution.md 第 6 节），改用 root 通道重启进程，
# 让它在正常启动流程里自己走一遍 enableInternal：

$ SPEC=m22_12.5.0.0A INDEX=0 python3 .tmp/root_shell.py 'kill -9 1326'
$ adb -s 127.0.0.1:5919 logcat -d -b all -v threadtime | grep -iE 'nfc|Watchdog'
06-25 20:59:05.328   799   836 I ActivityManager: Start proc 6839:com.android.nfc/1027 for restart com.android.nfc
06-25 20:59:05.365  6839  6839 I NfcService: Starting NFC service
06-25 20:59:05.366  6839  6839 I com.android.nfc: NfcAdaptation::InitializeHalDeviceContext: INfc::getService()
06-25 20:59:05.367  6839  6839 I com.android.nfc: NfcAdaptation::InitializeHalDeviceContext: INfcAidl::fromBinder returned ver(1)
06-25 20:59:05.393  6839  6858 I NfcService: Enabling NFC
06-25 20:59:05.397   569   569 I         : open: no nfc controller, reply OPEN_CPLT(FAILED) asynchronously
06-25 20:59:05.419  6839  6862 E libnfc_nci: nfc_free_conn_cb: invalid conn_id
06-25 20:59:05.419  6839  6858 E libnfc_nci: nfcManager_doInitialize: fail nfa enable; error=0x0
06-25 20:59:05.427  6839  6860 W libnfc_nci: gki_task_entry: task_id=4 terminating
06-25 20:59:05.428  6839  6858 W NfcService: enableInternal: Error enabling NFC

# 三处关键差异（与 log-fail.txt 第 B 节逐行对照）：
#   1. 20:59:05.397 那一行空 tag 的日志来自 HAL 进程 569 ——
#      `ps -A -o PID,PPID,NAME | grep nfc` → `569 1 android.hardware.nfc-service`，
#      即我们重写的桩（ALOGI 未设 LOG_TAG，所以 tag 列是空的）。
#   2. 距 `Enabling NFC` 只有 4 ms，开不了这件事当场就报出来了；
#      22 ms 后（20 ms 延迟 + 2 ms 传递）栈侧收到 OPEN_CPLT=FAILED，
#      打 `nfc_free_conn_cb: invalid conn_id` + `fail nfa enable` 并立刻返回。
#   3. 全窗口没有 `HalOpenInternal: Open Error=OK`，没有 `Watchdog triggered, aborting`，
#      没有 `JNI FatalError`，没有 `Start proc … for restart` 的第二次。

$ adb -s 127.0.0.1:5919 logcat -d -b all | grep -cE 'Watchdog triggered, aborting|JNI FatalError'
0
