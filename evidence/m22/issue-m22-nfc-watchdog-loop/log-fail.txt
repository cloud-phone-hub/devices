## B. 关键时序：`open()` 4~5 ms 就返回，"Open Error=OK"

重启后的进程（pid 8539）：

```
06-25 20:54:06.530  8539  8579 I NfcService: Enabling NFC
06-25 20:54:06.535  8539  8584 E libnfc_nci: HalOpenInternal: Open Error=OK
06-25 20:54:06.535  8539  8584 ... (此后 90 s 无线程推进)
06-25 20:55:36.532  8539  8580 E NfcService: run: Watchdog triggered, release lock before aborting
06-25 20:55:36.533  8539  8580 E NfcService: run: Watchdog triggered, aborting
06-25 20:55:36.534  8539  8580 F libnfc_nci: jni_internal.cc:826] JNI FatalError called: enableInternal
```

`Open Error=OK` 是本条的**核心误导点**：HAL 明明返回的是
`EX_UNSUPPORTED_OPERATION`，栈却打印 `OK`，因为
`NfcAdaptation::HalOpen()` 只根据「是否收到 `OPEN_CPLT` 事件」判定成败，
binder 返回异常被它丢弃了。

## C. tombstone 全线程栈：真正卡住的是 `AsyncTask #1`，不是崩溃线程

崩溃线程 tid 2693 名叫 `enableInternal`，实际跑的是 Watchdog（
`NfcService$WatchDogThread.run → nfcManager_doAbort → JNI FatalError`）。
用 python 按 `Cmdline:` 分块扫 tombstone，找到阻塞在 `CondVar::wait` 的线程
（`tombstone_08`，pid 9414 / tid 9433）：

```

backtrace:
      #02 pc 0000000000081894  /apex/com.android.runtime/lib64/bionic/libc.so (pthread_cond_wait+76)
      #03 pc 0000000000134e50  /system/lib64/libnfc_nci_jni.so (CondVar::wait(Mutex&)+48)
      #04 pc 000000000013a1f8  /system/lib64/libnfc_nci_jni.so (android::nfcManager_doInitialize(_JNIEnv*, _jobject*)+820)
      #07 pc 000000000011fcc0  /system/priv-app/NfcNci/NfcNci.apk (com.android.nfc.dhimpl.NativeNfcManager.initialize+0)
      #09 pc 00000000000f98b2  /system/priv-app/NfcNci/NfcNci.apk (com.android.nfc.NfcService$EnableDisableTask.enableInternal+410)
```

→ `enableInternal` 在 `nfcManager_doInitialize` 里等 `OPEN_CPLT`，等到 90 s
被 Watchdog 打断。这不是「open 慢」，是「事件永远不来」。

## D. AIDL 快照：失败只能靠事件表达（v1 没有 onOpenStatus）

`engine/vendor/out/android16/aosp/aidl/nfc/android.hardware.nfc/1/`：

- `INfcClientCallback.aidl` 只有 `sendData` 与 `sendEvent(NfcEvent, NfcStatus)`，
  **没有** HIDL 时代的 `onOpenStatus`。
- `NfcEvent.aidl`：`OPEN_CPLT=0` / `CLOSE_CPLT=1` / `POST_INIT_CPLT=2` /
  `PRE_DISCOVER_CPLT=3` / `HCI_NETWORK_RESET=4` / `ERROR=5`。
- `NfcStatus.aidl`：`OK=0` / `FAILED=1` / `ERR_TRANSPORT=2` / `ERR_CMD_TIMEOUT=3` / `REFUSED=4`。

旧桩 `nfc_service.cpp` 的实现是 `open()` 直接
`return ScopedAStatus::fromExceptionCode(EX_UNSUPPORTED_OPERATION)`，
其余方法一律异常 —— 一个 CPLT 事件都没回过。
