## 3. 等待链（反编译口径，与 15r / m22 / ss9380 / popsicle 同一条）

PersistentDataBlockService：
- onStart() 把初始化丢进 SystemServerInitThreadPool，末尾才 signalInitDone()；
- lambda 第一步 enforceChecksumValidity() 打开 ro.frp.pst 做校验和读写，
  节点不存在 → open() 抛 → 信号永不来；
- onBootPhase(500) mInitDoneSignal.await(10, SECONDS) 超时 → IllegalStateException
  → system_server FATAL → zygote 重启循环 → sys.boot_completed 永不置位。


## 4. 为什么「只补软链」不够（同链条机型的既有结论）

补软链后节点标签由 ueventd 按 `/dev/block/vda*` 命名规则给成 `misc_block_device`，
而 plat 只给 system_server 开了 `frp_block_device`；vda3 出厂是 0600 root:root，
system_server 以 system 身份跑，DAC 也过不去。两道缺任何一道都是同一条 10 s 超时链，
所以本次三件一起补（照抄 15r / m22 / ss9380 / popsicle 的范式）。
