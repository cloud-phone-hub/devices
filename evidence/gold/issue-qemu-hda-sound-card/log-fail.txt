# 修复前：/dev/snd 只有 timer，没有 PCM 节点（2026-10-27，实例 index 3，adb 5911）

## 1. 现象：只有与硬件无关的 timer

$ adb -s 127.0.0.1:5911 shell "ls -l /dev/snd/; echo rc=$?"
crw-rw---- 1 system audio 116, 33  timer
rc=0

# 自研 audio HAL 的输出路径要打开的是 /dev/snd/pcmC0D0p：
#   engine/vendor/hardware/android.hardware.audio/src/ModuleImpl.cpp（openOutputStream）
#   auto alsa = std::make_unique<cdh::audio::AlsaPcm>();
#   if (!alsa->open("/dev/snd/pcmC0D0p", kSampleRateHz, kChannelCount)) {
#       alsa.reset();          // 打不开就回退纯内存 VirtualDac，不阻断播放
#   }
# 缺节点 -> 回退内存 DAC -> AudioFlinger 的 burst 没有真实消费节奏的背压 -> 音频时钟偏快

## 2. 对照：实例 1（gold-15 原厂 ROM，adb 5919）同样只有 timer

## 6. 为什么只剩 timer

# timer 由 CONFIG_SND_TIMER=y 无条件创建，与硬件无关。
# controlC0 / pcmC0D0p 必须由具体声卡 probe 创建；没有 PCI 声卡设备，
# snd_hda_intel 不会 probe，所以 /dev/snd 下只有 timer。

## 8. 修复前的间接后果（对应 #24）

# HAL 回退纯内存 VirtualDac 时播放链路仍然通（REMOTE_SUBMIX -> scrcpy 有声），
# 但 AudioFlinger 写入不受真实时钟约束，在线视频表现为倍速播放（5~8 倍速）。
# 因此手机上看 /dev/snd 只有 timer 时，应先怀疑 QEMU 没接声卡，
# 而不是先去查 ALSA / HAL 代码。
