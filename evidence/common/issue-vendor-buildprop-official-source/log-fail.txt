## 3) 旧路径：副本就是装配基底

```go
// assemble.go（变更前）
allowedVendorFiles = map[string]bool{
    "build.prop": true,   // ← 静态树副本会进装配树，覆盖步骤 2 从 lineage 带出的那份
    "pci.ids":    true,
}
...
applyVendorBuildProps(plan, stdout)   // ← 步骤 6 直接在被覆盖后的文件上打补丁
```

结论：`manifest/<vendor>/<device>/vendor/build.prop` 同时承担「厂商原件留档」与「装配基底」，
本地改动写进去就生效、台账里查不到；一旦有人重新摘一遍原件，这些改动静默消失。
