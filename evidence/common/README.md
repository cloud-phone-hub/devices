# common：引擎级与跨机型条目

125 条，不属于任何单一机型：构建流水线的机制改造（内核上游回退、kernelsu）、跨机型的
vendor 装配口径（`vendor.replaces` / `vendor.lifts`、显示栈垫片编译、`build-prop-sets`
只认对象），以及跨机型的 `cdh_redirect` 推广与该规则表的数据形态（#137：12 份
`device.json` 的注释串外移到机型 README）、清单手写形态（#138：`hardware` 段统一成紧凑
单行）、`vendor/build.prop` 的基底来源（#139：07 现解厂商镜像，不留手抄副本）、
厂商 vendor 镜像的整树解包留档（#141：07 的取件 / build.prop / 标签真值共用 `super/unpack_vendor`；
该目录名自 #154 起按镜像名推导，独立 odm 分区的机型改用 `super/unpack_odm`，跨分区不再撞车）、
步骤 5 的来源归位（#142：`builtinFileOps` 删除、6 个 media 配置改官方直取、改过的件整份留静态树；`mode: patch` 评估后否决）、
机型清单与模板的对齐（#144：12 台 README 按 §3 骨架补齐、`brand`→`device`、模板 与索引口径修正）、
剩下的 `odm` 手抄副本迁移（#145：ss9380 / cph2797 / popsicle / 15r / oriole 五台的 `odm` 段落段、
静态副本删除，五台 `prop` 实测值分别是 `odm_a.img:/etc/build.prop`、`odm_a.img:/build.prop`（cph2797 / 15r 取顶层正文）、`vendor_a.img:/odm/etc/build.prop`（Pixel 6 无独立分区）；
运行侧逐机验收的截图工具（#147：websocket + RFB 客户端四处协议错，固化到 `core/host/daemon/tools/`）；
顶层 `kernel` 的填写口径（#148：厂商线与底包不同代时以底包为准，三台基线改正 + `Kernel()` 注释重写）；
属性收口的两处引擎级缺陷（#152：`proplines.Apply` 对 sets 命中的同名多行只改第一处，运行时被
init 的「后读覆盖先读」盖回；#154：06 的 odm 留档目录名写死 `unpack_vendor`，独立 odm 分区的机型
静默读到厂商 vendor 件、把 vendor 收口按厂商原值整层盖回）。
判定标准是「结论对所有机型成立」或「改动同时落在 3 台以上机型」——只对一台机成立
