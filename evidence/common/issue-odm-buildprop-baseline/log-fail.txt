# 失败证据：清单 odm.prop 仍写 /etc/build.prop（旧写法）

## 1) 旧写法指错了文件：odm 属性件在镜像的 /odm/etc/build.prop，不在 /etc/build.prop

```
$ cd out/roms/xiaomi/gold/OS3.0.10.0.VNQCNXM/super/unpack_vendor
$ ls -1 odm/etc/build.prop; ls -1 etc/build.prop; ls -1 build.prop
odm/etc/build.prop
ls: etc/build.prop: No such file or directory
build.prop
```

vendor 镜像里 `/etc/build.prop` 根本不存在（vendor 属性件在镜像根 `/build.prop`），
旧清单写法只能靠「退回机型静态树抄件」兜住 —— 真值于是变成手抄件。

## 2) 厂商原件本身是三档 abilist：先校验再套增量必然失败

```
$ grep -nE "ro\.odm\.product\.cpu\.abilist" odm/etc/build.prop

12:ro.odm.product.cpu.abilist32=armeabi-v7a,armeabi
13:ro.odm.product.cpu.abilist64=arm64-v8a
```
