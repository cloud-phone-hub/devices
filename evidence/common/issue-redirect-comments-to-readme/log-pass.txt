## 第 2 节：逐份校验（JSON 合法 + 规则序列逐条相等）

② 规则对象序列与改动前**逐条相等**；③ 除 `modules.redirect` 外整份 JSON deep-equal。

```console
$ python3 - <<'EOF'
import json,glob
ok=True
for p in sorted(glob.glob('manifest/*/*/device.json')):
    d=json.load(open(p)); red=((d.get('modules') or {}).get('redirect')) or []
    cm=[x for x in red if isinstance(x,str)]; ru=[x for x in red if isinstance(x,dict)]
    bak='out/tmp/devicejson-backup-20261103/'+p.replace('manifest/','').replace('/','__')
    bru=[x for x in (json.load(open(bak)).get('modules') or {}).get('redirect',[]) if isinstance(x,dict)]
    if cm or bru!=ru: ok=False
    print('%-42s 字符串%d 规则%2d 与备份一致=%s' % (p,len(cm),len(ru),bru==ru))
print('ALL OK' if ok else 'PROBLEM')
EOF

## 第 6 节：README 产出（popsicle 样例）

```markdown
# xiaomi/popsicle 机型层

Xiaomi 17 Pro Max（`popsicle` / `canoe`）的机型层参数与说明。

## modules.redirect（cdh_redirect 规则表）

`device.json` 的 `modules.redirect` **只放规则对象**：分段标题与逐段说明统一记在
本节，不写进数组——05 会把数组里的字符串元素原样渲染进 ramdisk 的
`lib/modules/cdh_redirect.rules`，注释混在清单里既难读，也容易被误当规则。
规则语法（`dir` / `file`、逆变换自动派生、顺序消歧）与注入路径见
[`engine/modules/cdh_redirect/README.md`](../../../modules/cdh_redirect/README.md)。

本机型共 **16** 条规则，顺序即匹配顺序（同一路径只应用最先命中的一条）。

### 规则表

| # | type | from | to |
| ---: | --- | --- | --- |
| 1 | `dir` | `/vendor/etc` | `/mnt/vendorpatch/vendor/etc` |
...（共 16 行）

### 原说明（含分段，按原数组顺序）

下面是这些说明原先在 `device.json` 数组里的样子（也是删注释前 05 渲染出的
`.rules` 全文）。现在数组只剩规则对象，05 渲染结果只保留 `dir` / `file` 行；
语义与取舍以本节为准。

...

```
