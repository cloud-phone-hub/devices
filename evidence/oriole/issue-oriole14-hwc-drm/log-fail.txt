# 结论：BufferInfoMapperMetadata（IMapper-4.0 元数据通路）此前被换成返回 nullptr 的桩，
# BufferInfoGetter::GetInstance() 退到 BufferInfoLibdrm，后者只认 "GBM Memory Allocator" /
# "DRM Memory Allocator" 两个名字，遇到 minigbm 的 "CrOS Gralloc" 直接判死 →
# ResourceManager::Init() 提前 return → 一个 connector 都没 attach → 服务端永不 hotplug。

## ④ 改「显示栈现编」后的五连坑（2026-11-01，逐条都是真报错原文）

# 坑 1：跑的是过期二进制。cdh 是 15:39 编的，lift.go（含 lineage:<分区> 支持）19:30
# 才写，于是 "system" 被当成版本段 → 报底包目录不存在。
$ ./out/bin/cdh device build oriole --manifest … --only 07_build_vendor --refresh
    输入: lineage-system 底包（借件集合 12 项）
[err] 阶段 build_vendor 失败: lineage 底包解包根不存在: out/roms/lineage/lineage-system
# 修：cd engine/build && go build -o ../out/bin/cdh .（改完 Go 代码必须重编这个二进制，
# 它不会自己跟着源码走）

# 坑 2：取链接用的 libsync.so 时漏了 system/ 前缀。lineage 的 system_a.img 是 system-as-root
# （镜像根就是设备根），库在 /system/lib64，不在 /lib64。
[err] 阶段 build_vendor 失败: 现编显示栈需要底包 system 分区的 lib64/libsync.so 参与链接:
      lineage-21.0 底包 system 里没有 lib64/libsync.so: 来源缺少该路径: lib64/libsync.so

# 坑 3：默认挑到 NDK 29，它的 libc++ 与 AOSP 14 的平台 __config_site 不兼容。
[err] 编译 drm_hwcomposer/bufferinfo/BufferInfoGetter.cpp 失败:
      #error _LIBCPP_HARDENING_MODE must be set to one of the following values

# 坑 4：链命令只给了 -Wl,…没给 --target，裸 clang++ 把 -Wl 交给宿主自己的 ld64。
[err] 链接 hwcomposer.drm.so 失败: ld64.lld: error: unknown argument '-soname'
      ld64.lld: error: unknown argument '--allow-shlib-undefined'

# 坑 5：-L 顺序把 NDK sysroot 排在最前，-lc++ 命中了 NDK 的 std::__ndk1。
[err] 链接 android.hardware.graphics.composer@2.4-service 失败:
      …service.o:(std::__1::__function::__func<…ComposerImpl<…>::createClient()::'lambda'()…
      >::operator()()) … referenced 1 more times
